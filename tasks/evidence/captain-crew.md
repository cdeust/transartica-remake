# Captain's wagon, crew and control panel: reverse-engineering notes (2026-09-27)

Offsets refer to `reference-private/unpacked/<script>.alis`. Listings are regenerated with `tools/alis_disasm.py --all-entries` and `tools/claude/alis_pretty.py`. Script IDs come from the header word: 0 main, 2 souris, 3 yoda, 4 train, 5 carte, 8 texte(k), 14 berta, 16 texte2(k), 19 room, 32 son, 45 sbras. `main+0x1c` is the hotspot code under the mouse ("matsou" at souris 0x440; the value comes from `ctstform` at souris 0x3bc via the form set chosen by `cforme`). The manual (Lemon Amiga, fetched in a browser) has no "captain's quarters", "command room" or "journal". Its wagons are **A engine, B private wagon "BOUDOIR", C GENERAL QUARTERS, D missile launcher**.

## 1. Control panel (yoda main loop 0x401–0x66b) — proven, labels from the manual
- **Train bar** (mouse y 41–48 from the bottom, 0x408): at x<14 or x>304 it scrolls `main+0x21` (0x1ac7). Otherwise, holding a wagon shows the textek −1 card (WAGON/TARE/STATE/TRANSPORT, 0x1b7c). The bar is drawn by 0x1979 from x=300 towards the left, with wagon 0 on the right. Sprite 92+type−1. Width 27 for types 5,10,17,21,23,25 and 33 for the others (0x1a90). State 1 adds cross image 121, state 2 adds two crosses, state 3 shows axle image 122.
- **Codes when a map is showing** (`main+0x2faa` 1..9, 0x43c): 1 = map icon (detailed→overall; overall→back to the wagon); 2 = clock (`main+0x2fce` toggles, time step `0x2fb8` 1↔3); 3 = direction reverser (0x18b9); 4 = detailed map; 5 = brake (`main+0x614a`); 6/7/8 = wagon icons (`main+0x20 = code−5`); 9 = D. D works only if `main+0x62c1` (missile launcher bought, glieu 0x27c3) and missiles (goods 2) are >0. Otherwise textek 15. The launcher is scene −2, which loads berta and sbras (yoda 0x10e1).
- **Codes in a wagon or city** (0x522): 1 = detailed map (from a city/scene: leave); 2 = clock; 3–5 do nothing (the manual confirms only the map icon is active); 6–8 = change wagon; 9 = D.
- **Which script each wagon uses:** `main+0x20 == 3` → `room.AO` (0x2eae); otherwise `train.AO` (0x2ece). train draws the engine when `main+0x20==1` (train 0x161) and the GQ otherwise (0x1bd). **Code 6 → engine and 8 → boudoir are proven. Code 7 → GQ is inferred.** Which icon (A/B/C) carries which code is set by form data that is not decoded.
- **Panel art (yoda):** base image 5 (0x3c7). Action-icon sets 57 (wagon), 58 (scene 0), 56/90 (maps), with form sets 2 or 6 (0x732). Image 91 greys out D. Brake indicator 120 and reverse indicator 124 (0x305a). Clock hands 20+h and 32+m/5 (0x2fc3, 0x300e).

## 2. Boudoir = room.alis (ID 19) — proven
Entry at 0x38: child processes for the stoup lamp (−7) and the alarm (−6). Then `cput 1` (background), `cput 19` if `main+0x64f5` (meaning unknown), `cputnat 16` on layer 3, form set 5. The hotspot switch is at 0xc0:
| code | object (manual) | effect |
|---|---|---|
| 10 | STOUP | if messages waiting (`main+0x614f`), pop one from `main[0x6152]` and show textek 98 (0x267) |
| 11 | Kolotov, secretary | fade out, then texte msg **100 = INVENTORY** (0xe4). Sets `main+0x651b=1` and `main+0x2fcc=0`; that this pauses time is inferred |
| 12 | revolver | textek 97 "…LEFT BUTTON… RIGHT TO CANCEL". Confirming shows image 21 on layer 77 and sends yoda msg 26 with 100 (0x121). That runs the mort.AO game-over (yoda 0x27d8) with texte2k 100 "THE CAPTAINS' BODY WAS DISCOVERED… KOLOTOV" |
| 13 | book | **save** (0x191): name of up to 8 chars A–Z/0–9 (0x55e, textek 38), backup-disk prompts (37/39/32), file `<NAME>.SAV` |

Save contents (0x787–0x8e7): 63 scalars plus the wagons, spies, mines, stoup, stocks, enemy trains, flags and map blocks. Loading happens in option 0x6c3.

**Inventory** (textek 0x2be7–0x3171) — proven. The page shows DAY `main+0x2fb2`, "PAGE n", NUMBER OF WAGONS, destroyed wagons, PTAV (tare, 10 per destroyed wagon), PTAC, TENDER CAPACITY (5000 per intact tender) and PRESENT CONTENTS (lignite+anthracite). Then one "NAME: count" line per intact type, in this order: 1,2,3,21,8–13,4,16,20,22–24,5–7,14,15,17–19. Each line is followed by "CONTAINING n unit" (0x33d4): 5/6 SLAVE(S), 7 MAMMOTH(S), 15 OIL, 19 PLANTS, 22 SPY (SPIES), 23/24 SOLDIER(S); goods are grouped by commodity. A new page starts with a click (0x3809). There are no actions.

**Stoup and radio.** The queue holds 10 entries; 0x1d1a pushes one, rings the bell (son 3) and lights the lamp. Ids 101+k are reports from spy k (0x27f4); 125–127 are story; <51 are not read. **No diary, journal or log screen is attested anywhere.** The "book" is the save.

## 3. General Quarters (train.alis, `main+0x20==2`, 0xe19) — proven
Background `cput 4`, plus 175 if `main+0x6514`, form set 19. Codes: 10 stoup; 11 radio operator → spy menu; 12 mock-up map → yoda msg 1 (overall map); 13 right-hand character → line-inspection-car menu.
- Spy menu (0xfb5, images 160/162/163, form set 34): send a spy (needs a slot with state 1 → yoda msg 12); dynamite (needs state 2 or 3 → msg 13); exit. With no spies it shows textek 9.
- Car menu (0x1042, images 157/161, form set 30): plain car (msg 10), car with missile (msg 11, needs goods 2), exit. Without cars (goods 3) it shows textek 8.
- 0x10fb: when `main+0x6514` is set, image 171–174 depends on the distance to (65,20). Meaning unknown.

## 4. Crew — mixed
| category | lives in (type: capacity, glieu) | source |
|---|---|---|
| slaves | 5 PRISON:60, 6 ALCATRAZ:100 | proven |
| soldiers | 23 BARRACKS:50, 24 XL BARRACKS:80 | proven |
| mammoths | 7 LIVESTOCK:3 | proven |
| spies | 22 SPY:5, plus 20 records `main[0x5d84]` (states 0 free, 1 aboard, 2 travelling, 3 posted) | proven (carte 0x1dc9 sets 1→2 and removes 1 from the type-22 load; TIME 0x0b43 sets 3) |

- Crew counts are wagon load `[3]`. The start is a six-wagon train with 10 soldiers in the BARRACKS (TABLE 0x699–0x6f4), proven.
- **There is no crew screen** where you assign, move or feed crew. Crew are seen only in the inventory, the wagon card, combat potential (textek 44) and HUMAN LOSSES (textek 81, 0x1c9f). Note: `personnel-story.md` calls 0x1dc3 a roster; it is actually part of the losses message.
- Uses: slaves as works labour (obstacles.md, yoda 0x2390); slaves and soldiers as beaters in the mammoth hunt (textek 0x1e50, partial); soldiers and mammoths in combat (manual).
- **Upkeep, food and morale: unattested.** No script lowers crew counts over time. The only writers are trade, losses, hunt and combat (textek 0x4d22+). Wages: soldiers cost only at enrolment (glieu).
- Train overview or reorder screen: no separate screen. Reordering is the workshop "move" action (glieu 0x21ea, code 50, msg 90). The algorithm is not decoded (partial).

## 5. Current remake

"journal" is a fixed intro text, labelled "CAPTAIN'S JOURNAL", with no original counterpart. `engine_panel.gd` is not referenced anywhere. `train_wagons.gd` holds the `0x2e1a` table and mass. **Missing:** wagon icons A–D, clickable and scrollable train bar with wagon cards, clock acceleration, reverser, boudoir (stoup, Kolotov inventory, save book, revolver), GQ (stoup, spy menu, car menu, map mock-up), stoup queue.

## Confidence
Proven: §1 codes and effects, room/GQ codes, save format, inventory, capacities, spy states. Manual: object names (Kolotov, revolver, book, radio operator). Inferred: code 7 = GQ, `651b` pause. Unknown: icon↔code placement, `main+0x64f5`/`0x6514`, stoup ids <51, reorder algorithm.

## Portage (2026-09-27) — rules ported to `game/scripts/{stoup_messages,inventory_report,quarters_actions,boudoir_actions,panel_hotspots}.gd`

Every rule below was re-checked against a fresh disassembly (`tools/alis_disasm.py --start <offset>` + `tools/claude/alis_pretty.py`, session of 2026-09-27), not copied from the summary above. `xdisasm.py`/`alis_disasm.py` give identical output; both were used interchangeably where one choked on an unsupported opcode near a given start address.

- **Stoup queue (`stoup_messages.gd`) — correction.** §2's "pop one from `main[0x6152]`" did not state an order. Push is at **yoda.alis 0x1d30-0x1db7** (not `0x1d1a`, which is out of range for every script this session checked — main.alis is only 6832 bytes; the write site is in yoda.alis): when the count (`main+0x614f`) is already 10, every slot is shifted down one (dropping the oldest, index 0), then the new id is written at `main[0x6152][count]` and count incremented. Pop, identical at **room.alis 0x267** and **train.alis 0x10ad**, does `count -= 1; read main[0x6152][count]`. So the stoup is a **capacity-10 stack that discards the oldest entry on overflow and reads the most-recently-pushed entry first (LIFO)**, not a FIFO queue as the name suggests. Confirmed the shown card is textek 98 at both sites.
- **Boudoir switch, verified exact at room.alis 0xc0**: `cswitch2 main+0x1c 3 -10 -> 0xd4,0xe4,0x121,0x191` (codes 10/11/12/13), matching §2 with no changes.
  - Revolver (**0x121-0x18d**): textek 97 prompt, a two-outcome wait on `main+0x1f`. The branch that does NOT fall through draws image 21/layer 77, `csend 1 LOC-40 26 100` (yoda msg 26, param 100) and reaches the game-over script; the epitaph is **texte2k 100 at offset 0x26e6** = "THE CAPTAINS' BODY WAS DISCOVERED..." (verified in `reference-private/city-scripts/texte2k-messages.txt`, switch header `# switch at 0x26d0 base -100`; ids 101-105 are the other death causes, out of scope here). Which raw button code means confirm vs cancel is a souris.alis question, correctly left out of `boudoir_actions.gd` (that module only exposes `revolver_confirm()`/`revolver_cancel()`).
  - Kolotov (**0xe4-0x11d**): confirmed `main+0x651b = 1` and `main+0x2fcc = 0` while texte2k 100 ("INVENTORY") is shown, restored after `csleep`; kept as INFERRED pause per §2, not upgraded to proven (the flags are set/cleared but nothing in this routine reads `main+0x2fcc` to prove it stops the clock).
  - Save name entry (**0x55e-0x5e4**): confirmed A-Z/0-9 only, backspace = key 8, confirm = key 187, lowercase folded to uppercase (`-32`) before the charset check — matches §2's "up to 8 chars A-Z/0-9".
  - Save fields (**0x787-0x8e7**): the exact 63 `main+` scalar addresses were read off directly (0x2fad through 0x6517, `cfwritev` per field) followed by 11 `cfwriteb` block writes (wagons/spies/mines/stock/etc., matching §2's summary). `boudoir_actions.gd`'s `build_save()` does **not** attempt a field-for-field mapping onto this list: the remake's save (`main.gd`'s `save_view()`) already uses a structurally different JSON dict (`version/wagons/trade/travel_camera/journey/network/session/discovery/...`), an existing, out-of-scope design predating this task. `build_save(name, state)` is a pure `(name, caller-assembled state dict) -> {filename, data}` mapper; it wraps whatever state the caller passes, named `<NAME>.SAV`, and refuses an empty name. Recording the 63-address list here rather than silently discarding it, per "no source, no implementation".
- **General Quarters, verified exact at train.alis 0xe19/0xe3b**: same 3-base-(-10) switch shape as the boudoir, codes 10-13 -> 0xe4e/0xe5e/0xf09/0xf14. All of §3 confirmed with no changes:
  - Spy menu gate (**0xe5e-0xf05**): a single pass over `main[0x5d84][k][0]`, k=0..19, sets `L0x1db=1` if any slot is state 1 (aboard) and `L0x1eb=2` if any is state 2 or 3 (travelling/posted); textek 9 only when **neither** flag is set. Inside the menu (**0xfb5-0x103c**, switch base -10 codes 10/11/12): send -> yoda msg 12 gated on the same aboard flag, dynamite -> yoda msg 13 gated on the same travelling/posted flag, exit -> `cerasen 1`.
  - Car menu gate (**0xf14-0xf9f**): `L0x10w` sums `main[0x2e1a][i][3]` (QUANTITY) where GOODS==3 (§2's "goods 3 cars"), `L0x14w` sums where GOODS==2 ("goods 2 missiles"), over **all** wagons regardless of STATE. textek 8 only when `L0x10w==0`. Inside the menu (**0x1042-0x10a7**, same switch shape): plain car (code 10) -> yoda msg 10 **unconditionally** (no re-check); missile car (code 11) -> yoda msg 11 gated on `L0x14w>0`; exit -> code 12.
- **Panel hotspots (`panel_hotspots.gd`), verified exact at yoda.alis 0x43c and 0x522** (both `cswitch2 main+0x1c 8 -1`, codes 1-9):
  - 0x43c (map showing): 1 toggles detailed<->overall (`jsr 0x1c39`/`0x1cda`); 2 clock (`main+0x2fce` 0<->1, `main+0x2fb8` 1<->3 — off->step1, on->step3); 3 -> `jsr 0x18b9` (reverser); 4 forces the detailed map; 5 -> `main+0x614a` toggle (brake); 6/7/8 all target the **same handler**, confirming `main+0x20 = main+0x1c - 5` exactly; 9 -> `main+0x62c1` gate then `jsr 0x672`.
  - 0x522 (in a wagon/city) — **correction**: §1 said "3-5 do nothing (the manual confirms only the map icon is active)". The disassembly shows this is not merely manual-attested: **the switch targets for codes 3, 4 and 5 are literally the post-switch `cstop`/wait instruction** — there is no handler code for those cases at all, upgraded from a manual claim to a bytecode-proven one. Code 1 here is not a bare "leave": it re-runs the identical detailed<->overall branch as 0x43c's code 1 (checking `main+0x2faa`). Codes 6/7/8 add a same-wagon guard not present at 0x43c (`main+0x1c != main+0x20+5`, i.e. re-clicking the current wagon is a no-op) before doing the same `main+0x20 = code-5` dispatch and re-drawing via `jsr 0x732`; this second, independent site again confirms `main+0x20==3 -> room.AO (0x2eae)` / else `train.AO (0x2ece)` (yoda 0x1ca3/0x1cab, also re-verified directly this session). Code 9 adds `main+0x2faa != -2` (don't re-enter the launcher scene while already in it) on top of the 0x43c gate.
  - Reverser (**0x18b9-0x18e2**): proven to release the brake unconditionally (`main+0x614a = 0`) as a side effect; the actual heading flip is inside `jsr 0x18e3`, which this session's tooling could not decode (unsupported opcode on that path) — **not** reproduced in `panel_hotspots.gd`, left as an explicit gap rather than guessed.
  - Launcher gate (**0x672-0x6d6**): sums `main[0x2e1a][i][3]` where GOODS==2 across all wagons; 0 -> textek 15, else scene -2 (berta/sbras) — confirms §1's "missiles (goods 2) >0. Otherwise textek 15" exactly.
- **Inventory (`inventory_report.gd`), verified exact at textek.alis 0x2be7 onward** — two corrections to §2's summary:
  1. **PTAV** (0x2c85-0x2caf): a destroyed wagon (STATE==3) contributes a **flat 10** to PTAV regardless of type; an intact wagon contributes its type's base weight. That base-weight table is computed by a **second, independent switch at textek.alis 0x36ae** (24 cases, types 1-24) which was compared value-by-value against `train_wagons.gd`'s `BASE_WEIGHT` and matches it exactly for types 1-24 — this cross-check confirms that table. Type 25 (BOILER) has **no case** in the 0x36ae switch (falls through with a stale value); `train_wagons.gd`'s `BASE_WEIGHT[24]=200` (sourced from TIME 0x2a77 per that file's own comment) is used as the safe fallback, flagged in `inventory_report.gd` as an undecoded edge case rather than silently trusted.
  2. **PTAC is printed as `L0xc8w + L0xb8w`** (0x2d4d), i.e. **PTAV + load total**, not the load total alone as §2's summary implied by juxtaposition. The load-weight-per-wagon table at **textek.alis 0x3780-0x3803** (base -5, types 5-23) matches `train_wagons.gd`'s `_load_weight` for types 5/6/23/24 (qty/10), 7 (qty*10) and 14/15/17/18/19 (qty) — **except type 21 (TENDER)**, which this routine special-cases to `main+0x2fb6 + main+0x2fc8` (current global lignite+anthracite), **ignoring the wagon's own QUANTITY field entirely**, added once per intact tender. `train_wagons.gd`'s own `_load_weight` treats 21 the same as 7 (qty*10); that is a discrepancy in `train_wagons.gd` this task's scope does not include fixing, only documenting. `inventory_report.gd` reproduces the textek.alis behaviour (fuel-based, per intact tender), since that is the routine actually being ported.
  - Contents-line strings (**0x33fc-0x348a**) read exactly: 5/6 → "SLAVE(S)", 7 → "MAMMOTH(S)", 15 → "TON(S) OF OIL", 19 → "TON(S) OF PLANTS", 22 → "SPY (SPIES)", 23/24 → "SOLDIER(S)" — §2's "OIL"/"PLANTS" were shorthand for the full decoded strings, now used verbatim.
  - Tender capacity (**0x2d5d-0x2da2**, a separate pass from PTAV/PTAC) and "PRESENT CONTENTS" (**0x2dec**, `main+0x2fb6+main+0x2fc8`) confirmed exactly as §2 states.
  - "NUMBER OF WAGONS DESTROYED" (**0x2ccb**) vs. "NO WAGONS DESTROYED" (**0x2cfa**) fallback confirmed; pagination click-through at **0x3809** confirmed ("DAY .. / PAGE n" reprinted after erasing layers 1-50).
  - Type-line order (`1,2,3,21,8-13,4,16,20,22-24,5-7,14,15,17-19`) was **not** independently re-derived this session (time-boxed out); it is carried forward from §2 marked "proven" there, and `inventory_report.gd`'s `TYPE_ORDER` const cites this file for that reason rather than a fresh offset.

Not ported (explicit, per the task's "not ported" boundary rather than a guess): the actual scene/UI effects of yoda msgs 1/10/11/12/13/26 and scene -2 (they live in map/scene/mort/berta/sbras scripts, out of this module's scope); the reverser's heading-flip body (`jsr 0x18e3`, undecoded); icon A/B/C -> code placement (form data, undecoded, per §1's own note); `main+0x64f5`/`0x6514` (meaning still unknown); stoup ids <51 (still unread by any decoded routine this session found).
