# CARTE.FIC : état des preuves sur le déplacement

Révision ALIS inspectée : `19a95afdc07b45d997467806d4dd1bf83c5f8076`. Les sources ALIS, les scripts décompressés et l’archive de données restent inchangés.

## Faits établis

- `main.co` ouvre `carte.fic` et lit 11 680 octets à l’adresse VM `0x76` : `/private/tmp/transarctica-ecs-observation/runtime.trace:1229817-1229818`. Le relevé statique indépendant est `data/map-bytecode-evidence.json` (`read_block_offset_hex=78d`).
- Le runtime exécute les appels de configuration de carte de `carte.co` aux offsets script `0x51e41` (`e3 cdefmap`) et `0x51e56` (`e4 csetmap`). Les paramètres observés figurent dans `runtime.trace:1681020-1681028` et `1681029-1681034`.
- Ces deux appels ciblent `0x76`. Dans `src/opcodes.c:4660-4692`, `cdefmap` stocke les dimensions et autres métadonnées précédant cette adresse. `src/opcodes.c:4787-4817`, `csetmap`, configure d’autres champs adjacents. Les valeurs observées sont des paramètres de cette structure ALIS; leur nom métier n’est pas établi.
- `carte.co` appelle `cputmap` avec la même adresse à l’offset `0x52583` (`runtime.trace:1681234`). `src/opcodes.c:4917-4975` crée l’élément de carte pour l’affichage et calcule un index de colonne circulaire par `map_pos % map_width`. `src/image.c:4074-4144` choisit ensuite des images depuis les codes de tuile. Cela établit un chemin de rendu, pas une règle d’entrée ou de sortie d’une case.
- Le consommateur non graphique trouvé dans la trace est `time.co` : aux offsets `0x3401f-0x3404d`, il lit un octet de `main+0x76` via `omaintc`, applique `abs`, puis fait un `cswitch1` (`runtime.trace:1546479-1546490`). La structure de dimension de `main.co` donne un pas 73 (`trace-index.json`, instruction 47 : `cdim 0x76 0x01 0x01 0x0049`); `tabchar` ajoute `73 × main[0x2fbe] + main[0x2fb1]` (`src/alis.c:1431-1458`, `src/opernames.c:223-227`). Dans l’image RAM F11, `main+0x2fbe = 00 0c` et `main+0x2fb1 = 3e`, soit coordonnées big-endian `(12,62)`; l’octet lu correspond à l’index `12×73+62=938`, et vaut `0x02` dans la RAM comme dans CARTE.FIC originale. L’instruction apparaît 87 fois dans l’index de trace compact, toujours avec résultat `abs(tile)=2` (`trace-index.json`, première ligne 1 546 479). D’autres chemins de `time.co` consultent également `0x76` (`runtime.trace:1581912-1581933`). Cela prouve une lecture indexée par coordonnées et des branches selon le code de tuile; la boucle temps seule ne prouve pas que ces branches valident un déplacement ni choisissent un aiguillage.
- Les tables de ces deux `cswitch1` sont récupérables depuis la copie RAM du script. `time.co` a son image de données à `0x33b98` (runtime.trace:1227151-1227152), de taille `0x2da8`; les offsets ci-dessous sont `adresse_VM - 0x33b98`, et `cswitch1` est défini par `src/opcodes.c:713-741`. Premier switch : opcode VM `0x3402e`, offset décompressé `0x496`, 20 comparaisons dans `[0x49a..0x4e9]`; valeurs 15→dest `0x4ee`, 16→`0x51f`, valeurs 38–52 et 55–57→`0x550`; toutes les autres passent par le défaut `0x4ea`. Le tile observé 2 prend donc le défaut. Second switch : opcode VM `0x35e24`, offset décompressé `0x228c`, 14 comparaisons dans `[0x229a..0x22d1]`; l’expression du switch est `abs(...)`, donc le cas -113 est inatteignable; les valeurs positives 34–37, 65, 67, 69, 78, 79, 107, 114, 116 et 120 vont à `0x22d6`; défaut `0x22d2`. Ces valeurs appellent le sous-programme à `0x22db`, dont `cswitch2` transforme le champ de direction local `0x34`: 1→9, 2→8, 3→7, 4→6, 5→5, 6→4, 7→3, 8→2, 9→1 (source `src/opcodes.c:744-765`, décodeur `alis_disasm.py`, bytes de l’image RAM). Les codes observés 2, 9, 14 et 24 prennent tous le défaut, sans transformation. À part, `time.co` commit aussi des valeurs locales vers `main+0x2fbe` (word) et `main+0x2fb1` (byte) aux offsets fichier `0x5f3` et `0x5f9`; la trace statique ne relie pas ces stores au switch de `0x228c`. Ces éléments prouvent le remappage de direction conditionnel et l’existence de commits de coordonnées, mais pas leurs deltas par code ni une règle d’aiguillage.
- `cwalkmap` (`src/opcodes.c:5681-5700`) appelle `walkland`, qui interroge l’altitude via `landalti` et accepte ou rejette un déplacement selon le relief (`src/opcodes.c:5523-5676`). Cette routine est la marche de terrain 3D générique; rien dans ce code ne la relie à `CARTE.FIC` ou aux aiguillages Transarctica.

## Conclusion et limite

Aucune règle prouvée d’adjacence, de delta autorisé, de blocage ferroviaire ou de choix d’aiguillage n’est établie. `time.co` branche bien sur les valeurs de la table, mais l’observation actuelle ne relie pas ces branches à une commande de trajet. Les valeurs `2`, `3`, `4` et `5` restent donc sans sémantique de circulation démontrée; le graphisme seul ne suffit pas. Je ne transforme pas la grille en graphe navigable.

Pour fermer cette question, il faut observer une commande de déplacement réelle, puis suivre dans `train.co`, `time.co`, `carte.co` et les scripts appelés les lectures du buffer `0x76` ou des coordonnées de ville, avec les états avant et après. Un relevé sans action de circulation ne permet pas de distinguer une tuile décorative d’une contrainte ferroviaire.
